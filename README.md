# Насколько защитный контекст улучшает модель Expected Goals

xG это оценка вероятности того, что удар закончится голом.
Обычные xG-модели знают геометрию удара и то, чем и как он нанесён.
Я проверил, что даёт добавление расположения защитников и вратаря в момент удара.

Пет-проект для ИАД ОГО.
Бюрчиев Тимур, БПИ 248.
Версия 1.0.0.

## Идея проекта

Главный вопрос звучит так.
Какую дополнительную точность прогноза даёт расположение защитников и вратаря?
Сравнение идёт с моделью, которая знает только геометрию и характеристики удара.

Это вопрос о качестве прогноза, а не о причинах.
Я не могу сказать, что плотная оборона вызывает промах.
Я могу сказать только то, что знание о ней помогает точнее предсказать исход.

Чтобы сравнение было честным, я разделил признаки на четыре уровня и добавлял их по одному.
Все уровни обучаются на одних и тех же ударах, одном разбиении и одной предобработке.
Тогда разницу метрик можно приписать именно новым признакам.

- L1, два признака: расстояние удара и угол ворот.
- L2, плюс пять признаков: часть тела, техника, тип ситуации и удар в касание.
- L3, плюс три готовых флага StatsBomb: `under_pressure`, `one_on_one`, `open_goal`.
- L4, плюс четырнадцать признаков: мой расчёт расположения соперников и вратаря.

Уровень L3 вынесен отдельно намеренно.
Это разметка провайдера, а не мой расчёт.
Если смешать её с уровнем L4, прирост от собственной геометрии окажется завышен.

## Данные

Источник один: StatsBomb Open Data.
Данные скачивает скрипт, вручную ничего делать не нужно.
Репозиторий источника целиком не копируется, он весит около 16 ГБ.

Ревизия источника закреплена номером коммита `b0bc9f22dd77c206ddedc1d742893b3bbe64baec`.
Без этого результаты перестали бы воспроизводиться, потому что StatsBomb обновляет данные.

Выборка: La Liga, Premier League, Serie A и Ligue 1 сезона 2015/2016.
Это 1517 матчей и 37 488 ударов без пенальти.
Доля голов 9.52 процента.
Из 37 888 событий удара я исключил 400 пенальти.
Ударов с неизвестным исходом, дубликатов и ударов без координат не нашлось.

Расположение игроков берётся из поля `shot.freeze_frame` внутри события удара.
Оно есть у 100 процентов ударов выборки.
Вратарь распознан у 99.9 процента.
Отдельные файлы StatsBomb 360 не нужны: ни один матч выборки их не имеет.

Полный разбор данных лежит в [reports/data_audit.md](reports/data_audit.md).

## Что я сделал

Разбил выборку на train, validation и test в долях 70, 15 и 15 процентов.
Разбиение идёт по матчам.
Удары одного матча не должны одновременно попадать в обучение и в тест.
Иначе оценка качества модели может оказаться завышенной.

Обучил лестницу моделей от базовой частоты голов до градиентного бустинга.
В неё входят логистическая регрессия, дерево решений и случайный лес.
Гиперпараметры подбирал внутри train с группировкой по матчам.
Тестовую часть я зафиксировал один раз и не использовал для выбора признаков или моделей.

Признаки, раскрывающие исход, в модель не попадают.
Это `statsbomb_xg`, сам исход, координаты после удара и поля про сейв и блок.
Имена игрока, команды и лиги тоже не попадают.
Проверка встроена в пайплайн и падает, если запрещённое поле попало в матрицу признаков.

Дисбаланс классов я не компенсировал.
Ни SMOTE, ни oversampling, ни веса классов не применялись.
Все они смещают вероятности, а мне нужна именно вероятность.

Главные метрики: log loss и калибровка.
ROC-AUC и PR-AUC приведены дополнительно.
Неопределённость считал парным bootstrap с ресемплингом матчей, а не отдельных ударов.
Удары одного матча зависимы, и bootstrap по строкам занизил бы интервалы.

## Результаты

| Модель | Признаки | Log loss | Brier | ROC-AUC | ECE |
| --- | --- | ---: | ---: | ---: | ---: |
| `statsbomb_xg` | внешняя оценка | 0.2404 | 0.0682 | 0.835 | 0.0168 |
| Логистическая регрессия | L4 с защитным контекстом | 0.2427 | 0.0692 | 0.830 | 0.0152 |
| Случайный лес | L4 с защитным контекстом | 0.2433 | 0.0694 | 0.830 | 0.0133 |
| Логистическая регрессия | L3 без защитного контекста | 0.2546 | 0.0721 | 0.802 | 0.0111 |
| Логистическая регрессия | L1 только геометрия | 0.2728 | 0.0770 | 0.760 | 0.0104 |
| DummyClassifier | базовая частота голов | 0.3137 | 0.0859 | 0.500 | нет |

Защитный контекст улучшает log loss на 0.0119 у логистической регрессии.
У случайного леса улучшение составляет 0.0107.
Оба доверительных интервала целиком лежат ниже нуля.
Улучшение устойчиво на этих данных.

![Ablation](reports/figures/04_ablation.png)

Готовые флаги StatsBomb дали только 0.0017 log loss, и интервал включает ноль.
Обнаружимого прироста от них нет.
Это не доказывает, что весь прирост принадлежит моим признакам.
Это два разных сравнения, а не проверка на исключительность.

Один признак вызывал у меня сомнения.
`n_opponents_visible` считает соперников в кадре.
Он отражает и плотность обороны, и границы поля зрения камеры.
Я переобучил модель без него на тех же ударах и том же разбиении.
Эффект сохранился: 0.0114 у логистической регрессии и 0.0103 у случайного леса.
Собственный вклад самого признака мал, и по log loss интервал включает ноль.

![Sensitivity](reports/figures/10_sensitivity.png)

Нелинейность почти не помогает.
На полном наборе признаков логистическая регрессия и случайный лес получили почти одинаковый log loss.

Со `statsbomb_xg` я сравниваю основную модель проекта.
Это логистическая регрессия с защитным контекстом.
Разница составляет 0.0023 log loss, интервал [-0.0009; +0.0052] включает ноль.
Устойчивого различия по log loss я не обнаружил.
Это не значит, что модели равны.
При объёме теста в 5639 ударов различие такого размера просто неотличимо от нуля.
По Brier score `statsbomb_xg` устойчиво лучше: разница 0.0010, интервал [+0.00004; +0.0019].
Сравнение неравное, потому что StatsBomb обучает модель на закрытых данных большего объёма.

![Калибровка](reports/figures/05_calibration.png)

Сырой log loss между лигами сравнивать нельзя, он ниже там, где реже забивают.
По качеству относительно базовой частоты разброс между четырьмя лигами получился небольшим.
Это не доказывает, что лиги можно считать одной популяцией.
Это значит только, что заметной разницы в качестве модели я не вижу.
Точечная оценка качества выросла от защитного контекста во всех четырёх лигах.
Слабее всего прирост в Ligue 1.
Отдельные доверительные интервалы по лигам я не считал.
Поэтому устойчивость прироста внутри лиги не проверена.

Больше всего log loss улучшается там, где вратарь вышел из ворот.
За ними идут удары со средней дистанции и ближние удары.
На дальних ударах и очень острых углах прирост мал.

Полный отчёт с таблицами лежит в [reports/results.md](reports/results.md).

## Ограничения

`shot.freeze_frame` показывает только игроков, попавших в кадр.
В среднем видно 7.5 соперника вместо десяти полевых.
Все счётчики означают "сколько видно", а не "сколько было на поле".

Работа отвечает на вопрос о качестве прогноза, а не о причинах.

Отсутствие эффекта у флагов StatsBomb не доказывает, что вклад принадлежит только моим признакам.

Выборка это четыре европейские мужские лиги одного сезона.
Переносить выводы на другие лиги, эпохи или женский футбол нельзя.

Все лиги относятся к одному сезону, поэтому проверить модель на другом сезоне я не могу.
Устойчивость проверяется только разрезом по лигам.

Сравнение с `statsbomb_xg` неравное по условиям.

Подгруппы в анализе ошибок пересекаются и выбраны после просмотра данных.
Доверительных интервалов для них нет.

Коэффициенты логистической регрессии стоит читать осторожно.
Защитные признаки коллинеарны и делят вклад между собой.

## Запуск

Нужен Python 3.11 или 3.12.
Проект работает на обычном ноутбуке.
Ни GPU, ни базы данных, ни облака не требуется.

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python.exe -m pip install -e ".[dev]"
```

На Linux и macOS вместо `.venv/Scripts/python.exe` используется `.venv/bin/python`.

Тесты и линтер работают без загрузки данных:

```bash
pytest -q && ruff check . && ruff format --check .
```

Оценить объём загрузки, ничего не скачивая:

```bash
python scripts/download_data.py --config configs/data.yaml --selection --dry-run
```

Полный пайплайн:

```bash
python scripts/download_data.py --config configs/data.yaml --selection
```

```bash
python scripts/build_dataset.py --config configs/data.yaml
```

```bash
python scripts/audit_data.py --selection
```

```bash
python scripts/run_experiments.py --config configs/experiment.yaml
```

```bash
python scripts/make_report.py
```

Загрузка занимает около 4.5 ГБ и кешируется.
Повторный запуск ничего не скачивает заново.
Обучение всех моделей с bootstrap занимает около 20 минут.

Результаты пересчитывать не обязательно.
Отчёты, графики и таблицы уже лежат в `reports/`, а исполненные ноутбуки в `notebooks/`.
Сырые и обработанные данные в репозиторий не входят.
