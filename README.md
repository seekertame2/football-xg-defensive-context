# Насколько защитный контекст улучшает модель Expected Goals?

Построение и сравнение футбольных xG-моделей на основе геометрии удара,
характеристик момента и расположения защитников и вратаря в StatsBomb Open Data.

Пет-проект для ИАД ОГО, Бюрчиев Тимур, БПИ 248.

## Исследовательский вопрос

> Какую дополнительную прогностическую ценность дают расположение защитников и
> вратаря по сравнению с моделью, которая знает только геометрию и характеристики удара?

Это исследование **качества прогнозирования**, а не причинности: утверждать,
что плотная оборона «вызывает» промах, нельзя.

## Основной результат

На 37 488 непенальтистских ударах из 1517 матчей четырёх мужских топ-лиг
сезона 2015/2016 самостоятельно рассчитанный защитный контекст даёт
**статистически устойчивое улучшение прогноза**.

| Модель | Признаки | Test log loss | Brier | ROC-AUC |
| --- | --- | ---: | ---: | ---: |
| `statsbomb_xg` (benchmark) | — | **0.2404** | **0.0682** | **0.835** |
| Логистическая регрессия | + защитный контекст | 0.2427 | 0.0692 | 0.830 |
| Случайный лес | + защитный контекст | 0.2433 | 0.0694 | 0.830 |
| Градиентный бустинг | без защитного контекста | 0.2523 | 0.0717 | 0.808 |
| Логистическая регрессия | только геометрия | 0.2728 | 0.0770 | 0.760 |
| DummyClassifier | — | 0.3137 | 0.0859 | 0.500 |

**Ablation по четырём уровням признаков** (одни и те же удары, одно разбиение,
одна предобработка), парный bootstrap по 1517 матчам, 95% интервалы:

| Шаг | Δ log loss | Интервал | Устойчиво? |
| --- | ---: | --- | --- |
| + характеристики удара | −0.0165 | [−0.0208; −0.0119] | да |
| + готовые флаги StatsBomb | −0.0017 | [−0.0035; +0.0002] | **нет** |
| + свой защитный контекст (логистическая) | −0.0119 | [−0.0160; −0.0078] | **да** |
| + свой защитный контекст (случайный лес) | −0.0107 | [−0.0153; −0.0063] | **да** |

Три вывода, которые стоит прочитать вместе:

1. **Защитный контекст работает.** Расстояние до ближайшего соперника, число
   защитников в конусе удара и положение вратаря дают устойчивый прирост
   поверх геометрии и характеристик удара.
2. **Это не заслуга разметки провайдера.** Готовые флаги StatsBomb
   (`under_pressure`, `one_on_one`, `open_goal`) значимого прироста не дают,
   поэтому эффект принадлежит именно самостоятельно рассчитанной геометрии.
3. **Нелинейность почти не помогает.** Логистическая регрессия с защитным
   контекстом не уступает случайному лесу: основную информацию несут признаки,
   а не форма модели.

Собственная модель немного уступает `statsbomb_xg`, но по log loss различие
статистически неубедительно (интервал [−0.0009; +0.0065] включает ноль).
Сравнение не равное: StatsBomb обучается на закрытых данных большего объёма.
Превосходить его проект и не обязан.

## Данные

Единственный источник — официальный репозиторий
[StatsBomb Open Data](https://github.com/hudl/open-data), привязанный к
неизменяемой ревизии `b0bc9f22dd77c206ddedc1d742893b3bbe64baec`.

Данные загружаются скриптом — вручную скачивать ничего не нужно. Репозиторий
источника не клонируется целиком: из 12.8 ГБ событий скачано 4.52 ГБ
утверждённой выборки, файлы StatsBomb 360 не скачивались вовсе. Сырые данные
не коммитятся.

Выборка: **La Liga, Premier League, Serie A и Ligue 1 сезона 2015/2016** —
1517 матчей, 37 488 непенальтистских ударов, доля голов 9.52%.
`shot.freeze_frame` доступен у 100% ударов, вратарь распознан у 99.9%.

Подробности и атрибуция — в [`DATA_SOURCES.md`](DATA_SOURCES.md),
аудит — в [`reports/data_audit.md`](reports/data_audit.md).

## Как устроен эксперимент

- **Единица анализа** — один удар. `is_goal = 1` только для исхода `Goal`;
  неизвестный исход — ошибка данных, а не молчаливый ноль.
- **Пенальти исключены** (400 ударов): это отдельный стандартизированный процесс.
- **Разбиение** 70/15/15 по `match_id`: удары одного матча никогда не попадают
  в разные части. Доли четырёх лиг расходятся не более чем на 0.3 п.п.,
  доли голов — на 0.07 п.п. Тестовые `shot_id` зафиксированы один раз.
- **Никакого leakage**: `statsbomb_xg`, исход, `end_location`, идентичность
  игрока, команды и лиги в признаки не попадают; проверка — в
  `assert_no_forbidden_columns` и в тестах.
- **Дисбаланс классов не компенсируется**: ни SMOTE, ни oversampling, ни
  `class_weight="balanced"` — перевзвешивание смещает вероятности.
- **Главные метрики** — log loss и калибровка; ROC-AUC и PR-AUC дополняют,
  но не заменяют их.
- **Неопределённость** — парный bootstrap с ресемплингом матчей, а не ударов.

## Установка

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python.exe -m pip install -e ".[dev]"
```

На Linux и macOS вместо `.venv/Scripts/python.exe` используется `.venv/bin/python`.

## Воспроизведение

Загрузка утверждённой выборки (4.57 ГБ, кешируется):

```bash
python scripts/download_data.py --config configs/data.yaml --selection
```

Построение датасета ударов и проверка схемы:

```bash
python scripts/build_dataset.py --config configs/data.yaml
```

Перегенерация отчёта об аудите по полной выборке:

```bash
python scripts/audit_data.py --selection
```

Лестница моделей, ablation и benchmark (около 20 минут):

```bash
python scripts/run_experiments.py --config configs/experiment.yaml
```

Графики, анализ ошибок и итоговый отчёт (секунды):

```bash
python scripts/make_report.py
```

Тесты и линтер:

```bash
pytest -q && ruff check . && ruff format --check .
```

Все скрипты поддерживают `--quick` для быстрой проверки на малом объёме.

## Ограничения

- `shot.freeze_frame` показывает только игроков в кадре — в среднем 7.5
  соперника вместо десяти. Все счётчики обороны означают «сколько **видно**»;
  число видимых включено в модель отдельным признаком.
- Выборка — четыре европейские мужские лиги одного сезона. Перенос выводов
  на другие лиги, эпохи или женский футбол не обоснован.
- Все лиги относятся к одному сезону, поэтому временной holdout невозможен;
  устойчивость проверяется разрезом метрик по лигам.
- Сравнение со `statsbomb_xg` не равное по условиям.
- Коэффициенты интерпретируются с осторожностью: защитные признаки коллинеарны.
